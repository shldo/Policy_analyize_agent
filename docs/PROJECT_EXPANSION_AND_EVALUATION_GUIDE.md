## 1. 总体判断与推进顺序

当前应先固定评分口径，再分批扩大问题与文档覆盖，最后基于新开发样本做优化。不继续围绕少数已知失败题反复调整提示词，也不一次性导入大量文件后才测试。

推荐顺序：

1. 固定答案评分口径，复核现有争议题。
2. 保存当前基线、语料和数据库的可恢复副本。
3. 选择第一批业务相关的新文档，完成来源与解析验收。
4. 分别建立“旧题抗干扰回归”和“新业务覆盖”两组实验。
5. 将开发问题扩到约 30–40 道，同时另建并隔离新测试候选。
6. 分层定位检索、重排、上下文、生成和引用问题。
7. 只在开发集进行单变量优化，保留无收益与退步结果。
8. 冻结方案，运行新独立测试，形成可复核的正式报告。
9. 接入通过验收的方案，补齐完整 Agent、页面、权限和故障恢复测试。
10. 完成本地复现包与客户演示，再决定是否上云；最后整理简历描述。

这些阶段按验收完成推进，不以某天必须得到高分为目标。本文不授权自动购买云资源、启用搜索付费服务或抓取不明范围的数据。

## 3. 阶段 A：先固定评分口径

### 3.1 每题区分三层内容

| 层次 | 含义 | 处理方法 |
| --- | --- | --- |
| 必答项 | 用户明确询问，或缺少后会改变执行含义的要点 | 遗漏计入完整性问题 |
| 可选补充 | 有帮助，但不属于回答问题所必需 | 不因缺少而扣完整性；写出后仍需有证据 |
| 禁止的错误扩展 | 无依据数字、强制程度、适用范围、条款归属或推断 | 独立记录支持性/范围错误 |

保留已有主体、action、condition_or_trigger、timeframe_or_exception 四字段。后续可新增明确的必答/可选标注，但必须版本化，并在跑候选方案前审核，不能看完结果再改变计分标准。

优先复核：

- DEV-SG03：原题只问列出三种模式，名称应是最低必答项；行为说明和混合架构例外是否作为加分说明，需确认。若需要解释，应另行明确题干，不事后将只答名称认定错误。
- DEV-TECH01：明确“what must it provide”是否同时要求实施形式与目的。新版本题干、gold 和评分要一致。
- DEV-TECH02：核心回答和额外展开分开审核；扩展到第三方产品时，不能忽略来源中的范围与例外。
- TEST-07/13：复核 v5 完整句答案；TEST-18/19 的中性题干不等于缺失事实已经确认。

产物：审核过的评分说明、逐题必答项、争议处理记录、数据版本。助手初审必须标明身份，不能写成客户或人工审核员已签核。

### 3.2 无答案与歧义分开

- `answerable`：当前固定语料提供足够证据。
- `unresolved_candidate`：暂未找到或全文审核尚未完成；不进入正式答案/拒答评分分母。
- `unanswerable_confirmed`：人工复核全部指定语料并记录后，确认该语料不建立所问事实。

新增文档可能改变上述状态，旧版的 confirmed 不能自动继承到新版语料。

问题明确但证据不足时，在 provided corpus / available material 范围内说明限制；不要强行追问、补数字，也不要断言现实世界不存在该事实。只有实体、国家、版本或意图存在会改变检索目标的歧义时才澄清。

## 4. 阶段 B：保护基线与数据分批扩容

### 4.1 扩容前先保存

- 原始 PDF、来源记录、SHA256 和许可/使用限制。
- 数据库可恢复备份、文档清单、片段和向量配置。
- 评测数据版本、代码提交、模型名称、实际提示词、原始运行报告。
- 当前数据/语料快照哈希及开发集、测试集的暴露历史。

当前快照哈希只用于变化检测，不是可恢复备份。必须在隔离环境试恢复，确认文档数、片段数、向量数与关键检索结果后，才能称为备份验证完成。

不要清空现有数据库，不在共享数据上运行破坏性集成测试。扩容优先使用独立实验数据库或隔离存储；记录独立项目名、端口与卷，防止误接旧数据卷。

### 4.2 第一批文档怎么选

建议首批新增约 5–10 份，而不是一次追求数百份。选择满足实际政策研究任务的官方材料：

- 与澳洲项目背景直接相关的政策、执行标准及案例。
- 支持合理国家比较的同类材料，而非无关领域拼接。
- 可控加入同主题的不同文件或版本，检验混淆风险。
- 新文档必须能带来真实问题，不只是增加片段数量。

之后是否扩到约 20–30 份，由业务覆盖、标注能力与前一批结果决定。这些是分批管理建议，不是达到该数量就自动合格。

OECD 相关页面是用户提供的候选来源入口，不能把网站宣称的政策数量当成本项目已有语料。后续应核对条目背后的原文、官方链接和可下载性。不能默认页面摘要等价于完整政策。

### 4.3 每份材料的入库检查

1. 记录标题、发布机构、国家/辖区、文档类型、语言、版本、生效日期（若有）、来源链接与获取时间。
2. 保存原文件与哈希，确认不是登录页、下载错误页或同一 PDF 的重复副本。
3. 检查正文、表格、标题、页码、OCR 和跨页断句；抽查包含期限/例外的关键段落。
4. 去重区分完全重复、版本更新和同主题不同文档；不能把旧版本当重复文件误删。
5. 建立片段与原文页范围映射，保留章节/条款信息；数量由文档结构决定，不按目标片段数切碎。
6. 确认向量模型与维度一致、无缺失向量、导入状态完整。
7. 发布新 corpus_version，再审核相应题目与锚点。

当前两份历史来源 PDF 的官方字节比对仍未完成，应先补来源完整性核验。若官方文件已更新，保存新旧版本，不覆盖旧基线。

### 4.4 现有执行器的限制

当前检索评测要求“全部已批准公开文档恰好等于清单”，新增文档会使旧清单校验失败。这是预期的防污染机制，不应删除检查来让实验通过。

做法：隔离旧语料恢复环境，或为新增语料建立新 manifest 与审核过的数据版本。旧问题在新 corpus 下运行也需新版本记录；如果新文档改变了适用答案，先改标注而不是直接比较旧 gold。

## 5. 阶段 C：扩充问题，建立两条评测线

### 5.1 两条线不能混成一个分数

| 实验线 | 保持什么不变 | 用途 |
| --- | --- | --- |
| 旧题抗干扰回归 | 问题、有效 gold、模型与检索参数 | 判断新增语料是否造成混淆 |
| 新业务覆盖评测 | 预先确定的业务分类和评分规则 | 判断系统是否能处理新增材料带来的任务 |

如果旧题答案随新版本政策发生变化，该题退出“答案不变”的抗干扰对照，转入版本更新场景。报告同时列出保留题、退出题及原因，不悄悄改变分母。

### 5.2 开发集建议扩到约 30–40 道

覆盖以下任务，不强制平均分配：

- 适用主体、辖区、政策范围。
- 截止日期、启动条件、执行动作和交付物。
- 推荐与强制要求、例外和前提。
- 相邻条款与相似概念区分。
- 多处证据共同完成一个真实任务。
- 不同国家或版本的比较，但不得为跨文档而刻意配对。
- 语料不足的真实问题与需要澄清的真实歧义。

每题必须能解释“什么用户、为什么会问、答案支持什么行动”。题目英文，审查总结中文。无需按文档长度平均分题，避免一本长标准主导全部指标。

### 5.3 新的独立测试

建议另建约 20–30 道测试候选作为下一阶段起点；审核工作量允许后再扩大。开发与测试按业务意图、关键证据、政策主题分组，避免仅换措辞。

v4 已观察，v5 又源于 v4，因此它们是历史测试/回归材料，不再是新的未见测试。新测试题审核后隔离，开发期间不查看排名或输出；正式运行后记录暴露时间。如果据此修改系统，之后的运行称为回归。

## 6. 阶段 D：分层诊断，不混用指标

| 层次 | 主要观察项 | 不可替代的内容 |
| --- | --- | --- |
| 文档处理 | 来源有效、解析完整、版本清楚、锚点可映射 | 文件存在不等于正文可用 |
| 初始检索 | Hit@20、已标注证据组覆盖率@20、缺失题数 | 不等于生成正确 |
| 重排 | 全证据@5、MRR@10、逐题升降 | 重排找不回候选池外证据 |
| 上下文装配 | 是否截断、重复占位、条款/页范围是否保留 | 排名里存在不等于模型实际收到 |
| 生成 | 必答项覆盖、事实支持、条件/例外与强制程度 | 关键词出现不等于回答完整 |
| 引用 | 编号合法、陈述支持、条款归属与定位 | 编号不越界不等于引用准确 |
| 拒答/澄清 | 应答、证据不足、澄清选择是否适当 | 不可用未决题制造拒答高分 |
| 完整 Agent | 路由、工具参数、权限、终止、状态隔离 | 固定上下文生成不是端到端 Agent |

建议保持的计分定义：

- Hit@k：一题至少一个已标注必要证据组被命中。
- 证据组覆盖率@k：该题命中组数/全部必要组数，再做逐题宏平均。
- 全证据@k：必要组全部命中的题数/可计分题数。
- MRR@10：首个已标注相关结果的倒数排名，前 10 未命中记 0。
- 生成完整性：按事先审核的必答项计算；同时报告整题完整率和分母。
- 支持性：按实质性陈述检查，并单列无依据扩展与原文矛盾；粒度应先固定。
- 引用支持率：明确分母是引用关联、陈述还是题目，不混用。

当前没有穷尽所有相关片段标签，不把证据组覆盖率包装为标准 chunk Recall。语义评分方法尚需实现和人工校准，不能从现有检索 JSON 自动得出。

## 7. 可能出现的结果与处理预案

以下均为条件性预案；出现现象后先验证原因，不直接认定。

| 可能结果 | 优先排查 | 推荐措施 | 再验证 |
| --- | --- | --- | --- |
| 新增文档后旧题基本稳定 | 是否真加入了新文档；样本是否太简单 | 增加合理相似干扰与新任务，不刻意制造失败 | 两条线分开报告 |
| 旧题下降、新题表现好 | 新文档抢占前排、标签是否漏等价证据 | 先审核证据，再试辖区/版本过滤和混合检索 | 同题逐项升降表 |
| Hit@5 不变，全证据@5 下降 | 只命中主要要求，遗漏条件/例外 | 去重、证据多样性、多子问题检索或预算重分配 | 看全部必要组，不只看首个命中 |
| Top-20 已缺证据 | 解析、切片、关键词/语义失配 | 先修数据，再对比 BM25/RRF、查询分解或召回窗口 | 固定重排器测候选覆盖 |
| Top-20 齐、top-5 不齐 | 重排目标与必要证据不一致 | 比较去重/分组选择/上下文预算；必要时换重排器 | 全证据@5 与生成效果同时看 |
| 加大 top-k 检索升、回答降 | 噪声、冲突、重复、长上下文遗漏 | 保留条款边界、减少重复、分层选择证据 | 同时报告 token 和完整性 |
| 混合检索无收益 | 原题天花板、词法分析或融合截断 | 保留原方案，扩大有效开发任务，不为架构名词上线 | 新开发分类结果 |
| 混合检索有收益但更慢 | 多一路检索和候选处理开销 | 量化延迟/成本，决定是否仅部分场景使用 | 相同负载与冷/热条件 |
| 重排 MRR 上升但答案没好 | 排序之外的遗漏或上下文使用失败 | 进入生成/引用诊断，不继续只调 reranker | 固定上下文的生成对照 |
| 证据齐全但遗漏操作 | 过度压缩、必答项理解不足 | 通用结构化要点抽取或答案核验实验 | 必答项覆盖与新增错误 |
| 答案更长但错误更多 | 非必要扩展、条款归属混合 | 限定回答范围；补充陈述也检查条件和出处 | 支持性、完整性分别计分 |
| 提示词改了局部好、其他退步 | 过拟合与 API 波动 | 保留基线，固定口径后重复小样本，必要时拒绝上线 | 全开发集而非仅失败题 |
| 不同国家/版本混答 | 元数据不全、查询范围不清 | 补元数据；明确范围后过滤，真正歧义才澄清 | 辖区/版本错误数 |
| 新文档让原拒答题可回答 | 语料可回答性变化 | 新版本重标答案与证据；旧拒答结果留历史 | 不继承旧 confirmed 标签 |
| 未决问题直接回答 No | 将检索失败当作不存在 | 改为语料范围的证据不足表述 | 人工全文核验后的拒答集 |
| 存在引用但归错条款 | 相邻内容混在同一片段 | 保留条款标识；核验陈述与条款关系 | Criterion 级归属，不只文档级 |
| 向量缺失或模型不一致 | 部分导入失败、活动模型切换 | 修复缺失批次，记录模型/维度后再跑 | 数据完整性门禁通过 |
| 跨次结果波动明显 | 数据变化、服务版本、近似检索、模型随机性 | 固定输入、保存配置，做重复运行并报告范围 | 不挑最好的一次 |
| 新测试明显低于开发集 | 泄漏、覆盖不足、开发过拟合 | 如实发布差距，再建下一轮开发任务 | 旧测试不再冒充未见 |
| 新数据使所有指标都大涨 | 题变简单、分母变化、标签泄漏 | 审计切分、gold、候选过滤和失败排除 | 校验成立后才承认收益 |

## 8. 优化实验的执行纪律

每轮只改变一个主要因素；若改变模型、切片和提示词三项，无法知道谁产生收益。

建议顺序：数据质量 → 范围/版本元数据 → 召回 → 重排/上下文 → 生成 → 引用 → 完整 Agent。

- 任何源文档可作为数据，不作为执行指令；测试文档中的命令不能获得系统权限。
- 初始候选数与重排候选数记录清楚。混合方案候选上限相同，也不代表计算成本相同。
- 新生成步骤若增加一次模型调用，记录两次用量与失败率，不只看最终答案。
- 参考答案只用于审核，不能出现在待评模型的请求中。
- 同一模型生成并自评存在偏差；自动 judge 只能辅助，需与人工抽样核对分歧。
- 保留 baseline 与 candidate 原始输出，不以“修复后的答案”替换原始结果。
- 已知失败样例可作回归，但不能成为唯一优化目标。

每轮记录：数据版本、语料版本、代码提交、模型及参数、提示词、抽样/切分、成功/失败/未决数、指标分母、逐题变化、token、耗时、决定与限制。

## 9. 阶段 E：完整 Agent 与产品验收

以下是后续验收安排，不能用本次固定上下文结果代替。

### 9.1 Agent 与工具

- 直接问答、确实需要多步检索、需要澄清的请求是否选择合理路径。
- 工具调用参数、返回结构、超时、错误处理与最大步数是否有效。
- 多轮会话状态是否隔离，失败后是否可恢复，不泄露其他用户历史。
- 禁止访问的文档是否在召回前即被排除，而非生成后再隐藏。
- 文档中的 prompt injection、伪造工具指令是否被当成普通数据。
- 记录任务完成率、工具错误率、无效循环及失败原因；样本与定义需独立建立。

MCP 只在确有工具接入需求时纳入交付，不为简历词汇额外引入。采用时测试 schema、权限、错误、审计和最小访问范围。

### 9.2 后端与数据库

- 导入幂等、去重、失败重试、状态更新、版本筛选与权限过滤。
- 新模型向量表与原模型隔离，切换后查询与存储模型一致。
- 迁移脚本与回滚/恢复流程在独立测试数据库验证。
- 并发、限流、连接池、超时与清晰错误信息；不要靠吞异常返回成功。
- 使用真实但小规模的负载测试，避免对用户数据库执行破坏性清理。

### 9.3 前端与客户演示

- 展示文档导入状态、版本、引用片段及页范围。
- 点击引用定位到正确 PDF；起始页正确不等于引文所在精确页正确。
- 流式回答、失败状态、取消操作、历史恢复及权限边界可见且可解释。
- 明确展示回答范围：本地语料、使用了哪些文件、Web Search 是否启用。
- 演示至少包含正常问题、条件/例外问题、证据不足问题与一个可解释失败，不只展示精选成功例。

### 9.4 性能

另做性能实验，分别记录冷启动、热启动、检索、重排、首 token 与完整回答耗时。报告 p50/p95 时同时报告样本量、并发、硬件与模型配置；少量样本的 p95 不作为可靠服务承诺。

性能变差时先区分模型下载、CPU 重排、网络 API、数据库查询和上下文长度，再考虑缓存、索引或服务器，不直接购买云机器来掩盖质量问题。

## 10. Web Search 与云服务器：延后、分开验收

当前不配置 Web Search。未来确有客户需求并获得服务配置后，再单独处理：

- 本地资料不足时的搜索触发规则、允许来源、来源日期与访问失败。
- 网页搜索只是发现入口，必要时提取原文；搜索摘要不自动算完整证据。
- 保留搜索请求、返回来源与内容快照，防止网页变化使结果无法复查。
- 防止 SSRF、恶意页面指令和凭据泄露，不绕过登录或访问限制。
- 分开报告固定语料模式与联网模式，不能用联网答案补固定语料测试后仍称同一实验。

先完成本地复现和稳定 Demo，再根据实际 CPU/内存/API 并发与演示需求决定云部署。云验收应包括 TLS、鉴权、最小开放端口、凭据管理、备份、日志脱敏与费用上限。是否采购由用户确认。

## 11. 验收门槛与暂停条件

不先承诺统一的“90% 准确率”。扩容初期先报告实测，再由业务风险与用户审核确定质量门槛。

可以现在固定的门禁：

- 数据哈希、来源清单、片段映射和向量完整性必须通过，否则不出质量结论。
- 未决题不计正式语义分数；失败调用必须列出，不能从分母悄悄删掉。
- 权限泄露、伪造依据或严重错误适用范围属于阻断问题，不能被平均分掩盖。
- 新方案没有明确质量收益却增加复杂度/成本，不默认上线。
- 小幅波动先做逐题复核，不将一题变化宣称为普遍提升。
- 独立测试一旦用于调参，即记录为已观察，不再重复称首次验证。
- 备份无法恢复、语料来源不清、评分存在关键分歧时，先修对应基础环节。

在每阶段总结中作出四选一决定：继续扩容 / 做一个定位明确的优化 / 保持现状 / 暂停并请求具体审核。说明证据，不以单个好看的指标决定。

## 13. 交付与简历使用边界

最终交付应包括：来源清单、可恢复的数据准备流程、版本化评测、配置模板（无密钥）、可重复执行入口、原始结果索引、中文分析、已知局限和客户 Demo 操作说明。

当前可描述“建立固定政策语料上的版本化评测与重排对照，首次 16 题测试中 MRR@10 从 0.641 到 0.851”。必须保留样本规模与指标性质，不改写成“回答准确率提升到 85%”。

扩容后只用最终真实测得且可复查的规模和指标。混合检索尚未显示收益、实验提示词未被采用，也可以作为面试中的方案取舍与负向实验经验，不包装成已上线提效功能。
