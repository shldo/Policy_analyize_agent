# 生成评分口径 v1 · 已批准

状态：陈昶宇于 2026-09-07 在对话中确认优化内容，批准本评分口径。版本：generation-rubric-v1。批准的是规则与后续改题方向，不等于逐题模型答案或 v5 新措辞均已审核通过；不重算历史成绩，不修改旧 gold。

## 1. 原则

- 问什么，最低答案就必须回答什么；参考答案中额外的教学说明不自动成为必答项。
- 影响实际行动的对象、交付物、条件和期限，不能只因为问题没有逐字列出就省略。
- 可选补充不写不扣完整性；写出来必须正确、有依据并保留相关例外。
- “回答完整”和“额外陈述正确”分开。回答了核心问题后又作无依据限制，不得算成完全合格。
- `may / should / must / only` 的改变、辖区/版本混淆及条款归属错误独立记录。
- 新规则确定后应用于 baseline 与 candidate 两边；因已看过输出，本轮仍属于开发集回顾，不是盲测。

## 2. 13 道开发题的执行口径

| ID | 必答项（建议） | 可选补充 / 注意事项 |
| --- | --- | --- |
| DEV-AU01 | 至少每年复核；AI approach 显著变化或新因素实质影响准确性时提前更新 | 网站放置位置不必展开 |
| DEV-AU02 | DTA；发布或更新时；通过 ai@dta.gov.au 发送声明链接 | 只说发邮件但不说链接，不足以指导完成通知 |
| DEV-AU03 | 政策生效后 6 个月内制定战略立场 | 战略目的、如何向员工传达可选；写出则须有支持 |
| DEV-AU04 | 每 6 个月分享；从为满足要求而建立登记册时起算 | 可复用旧登记册等不是问题核心 |
| DEV-AU05 | 全体员工；强制负责任 AI 培训；政策生效后 12 个月内 | 培训渠道与附加角色培训可选 |
| DEV-SG01 | MCP 对应 agent-to-tool；A2A 对应 agent-to-agent | 协议生态发展可选；不能说只有这两种协议 |
| DEV-SG02 | 设计/系统约束可阻止违规工具调用，不依赖模型遵守提示，因此更可靠 | 对不可靠约束增加监控/HITL 是相关补充；原题问 why，建议不将该补充遗漏直接计入核心完整性失败。补充后不得增加未经支持的 only 限制 |
| DEV-SG03 | Sequential、Supervisor、Swarm 三种名称 | 按现题“what three patterns”建议行为说明及混合架构例外为可选；若必须解释，应新版本改成 name and explain |
| DEV-TECH01 | 按字面最低要求：直接影响用户的 AI 生成媒体内容这一触发范围；透明性、来源与作者信息 | 可视水印与元数据是实施要求。建议未来题干明确询问 what measures；在题干修订获准前，对该项只报严格 gold 下遗漏，不强行记入最低必答失败。Criterion 23/WCAG 补充必须明确条款来源 |
| DEV-TECH02 | 端到端开发生命周期的版本管理 | Criterion 18 编号可选；扩展到第三方产品、数据/模型要求时应保留相关范围，原文层级有疑义则明确说明而非自行合并 |
| DEV-TR01 | 大约 20–30 分钟 | 不得改成固定 20 分钟或承诺所有人 30 分钟内完成 |
| DEV-TS01 | 不强制列出个别 use case 或个案细节 | 自愿补充为重要限定，建议保留；不能扩展成禁止公开 |
| DEV-TS02 | usage patterns 与 domains 两维度 | 分类例子可选，不得把例子误当全部分类 |

以上与旧 required_answer_points 的粒度可能不同。只在用户确认后发布独立 rubric 版本，不静默覆盖旧标签。尤其 SG02、SG03、TECH01 的变更会影响完整性分数，不能称其为模型质量提升。

## 3. 评分记录

每题分开记录：

1. **完整性**：每个必答项 `covered / missing / ambiguous`，列出依据；ambiguous 先送审，不自动算对或错。
2. **支持性**：实质性陈述 `supported / unsupported / contradicted / unclear_scope`，记录对应引用或遗漏的边界。
3. **引用**：编号有效性、陈述支持、条款归属、文件/页范围分别检查；跨页片段不能冒充精确证据页。
4. **规范与范围**：是否强化约束、混用国家/版本、遗漏会改变已表达结论的例外。
5. **最终审核状态**：`pending / approved / needs_revision`；注明审核人、日期、rubric 版本。

初期不将这几维加权为一个总分。分维报告更容易定位问题。正式完整率分母只含口径确定且完成审核的题，同时列出其余题目及排除原因。

`answerable` 不等于模型必须不加限定地回答全部细节；若实际提供上下文缺少证据，可承认不足，但检索/任务完成度仍应记录损失。

## 4. 已确认的执行决定

- SG03：只列三种名称即可满足当前题干核心要求，解释与混合架构属于可选补充。
- SG02：监控/HITL 为可选补充，不作为 why 问题的独立必答项；写出时仍须准确。
- TECH01：后续新题版本明确询问触发条件、措施与目的；当前版本仍按字面最低要求评分，不把改题后的严格标准套回旧题。

本规则与旧标签粒度差异单独记录。下一次正式评分引用 generation-rubric-v1；历史结果保留其原规则，不宣称仅由口径改变带来了质量提升。
